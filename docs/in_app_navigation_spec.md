# 画面全体を再読み込みしない遷移（2026-09-13）

## As-Is / To-Be

| 対象 | As-Is | To-Be |
|---|---|---|
| ホーム・共通メニュー・求人/応募などの内部リンク | URLへの通常遷移で文書と接続を読み直し、白い時間が発生 | 共通コンポーネントで同じパスの内部リンクを受け取り、既存セッションのquery_paramsを更新して表示を切り替える |
| 保存して次へ等のStreamlitボタン | サーバー再実行中、処理が進んでいるか分かりづらい | ボタン押下・スクリプト実行中に画面上部の処理中案内を表示し、完了で消す |
| 外部URL・別タブ・ダウンロード・ページ内アンカー | 通常のブラウザ動作 | 維持 |

## 実装

- `ui/navigation_bridge.py`：Streamlit v2 componentを1回定義、全ページ共通のapp.pyで認証と本人ID確認の直後に配置。コールバックは遷移パラメータのみ更新する。ページ名と入力サイズをサーバー側でも検証。保存や認証を代行しない。
- `ui/navigation_bridge.js`：documentのリンククリックを委譲受信。同一origin・同一pathname・対応page・通常クリックに限定。URLや入力内容をHTML化しない。書換え対象はサーバーの遷移先だけで、既存リンクの見た目を維持。
- 求人ID、比較ID、応募ID、focusなどのクエリを渡し、以前のクエリは置換する。既存の本人確認・所有者確認と保存後のnavigate_to_pageは維持。
- ネイティブの保存ボタン自体は引き続きStreamlitのコールバックと再実行を使用する。ブラウザ文書を読み直さないことと、サーバー処理がなくなることを混同しない。
- 処理中案内は個人データを含まず、元画面のコピーも作らない。リスナーはコンポーネント終了時に解除。スクリプト実行状態の検知にStreamlit 1.60.0のDOM属性を使用しており、将来の更新時に確認が必要。

## 検証と限界

ローカルStreamlit 1.60.0＋Edgeで内部リンク、保存ボタン、求人ID付きリンクを確認。文書リクエストは初回の1回だけ、セッション識別値と入力値が維持された。クリック直後の処理中表示と完了後の消去を確認。外部リンク、別タブ、Ctrlクリック、ダウンロード、アンカー、未対応ページを横取りしないことも確認。

初めてサイトを開くとき、ブラウザの再読み込み、Googleログイン等の外部遷移、接続切断からの復旧では読み込みが発生する。JavaScriptコンポーネントが利用できない場合は通常リンクへ戻る。DB/AI処理そのものの時間をなくしたり、全ケース3秒以内を保証する変更ではない。公開検証はpublic_release_status.mdへ記録。

[Streamlit公式v2 component仕様](https://docs.streamlit.io/develop/api-reference/custom-components/st.components.v2.component)のリンクをPythonへ通知する方式を使用。

公開初回確認で、認証前のコンポーネント登録は初回本人設定時のsession_state初期化に消され、1回目のクリックが反映されないことを確認。登録を認証後へ移して対応。未ログイン画面・データ説明単独画面は従来の通常遷移となる。

## 2026-09-13 求人確認操作の部分更新

確認不要・元に戻す・確認結果保存・取り消しは評価領域のfragment内だけを再実行する。navigation_bridgeは同領域の処理に遷移待ちバナーを出さない。AI完了は処理中だけの部分更新で取得する。入力フォーカスがある間はポーリングを延期する。実際のページリンク遷移は従来どおり。

### 保存後の表示位置（2026-09-13追記）

As-Is：部分更新だけでは、折りたたみや保存済み項目の移動後の表示位置を維持できない場合があった。
To-Be：固定キーで折りたたみを識別し、保存時の次の入力項目を更新後の画面内に保つ。クリック時にブラウザ内へ一時保持するのは求人ID・要素キー・スクロール位置のみで、入力内容を複製しない。10秒で失効し、手動スクロール時に破棄する。DOM依存のためStreamlit更新時は再確認する。

## 2026-09-13 一括保存と入力フォームの独立

As-Is：各確認フォームの保存が評価領域の再実行を要求していた。
To-Be：一つのフォームで全項目を送信。保存後は件数と通知だけを描画し、フォーム再実行を追加要求しない。スコア・評価一覧が通知を受けて別fragmentで更新する。フォームの項目一覧は開いた時点の構成を維持し、AI完了で並べ替えない。保存ボタンがフォーム末尾にあるため、保存後もその位置で完了を表示する。

### 2026-09-13 保存時だけ確認欄を更新

As-Is：フォームの構成を固定したため、保存成功表示と確認不要等の一覧表示が食い違った。
To-Be：保存完了後のみ詳細fragmentの確認データを読み直して分類を反映。スコアの定期更新ではフォームを再描画しない。一括フォーム保存では保存直前のスクロール位置を復元する。


## 2026-09-13 お知らせ・確認項目の表示整理

- As-Is：ホーム上部の小さいポップオーバーにお知らせ本文を表示。「点数への反映」は常時表示し、確認済み・許容した項目を別一覧に表示していた。
- To-Be（実装）：上部のお知らせリンクから専用ページ `?page=announcements` に移動し、既存本文を通常の文字サイズで全文表示する。既存の内部ナビゲーションを使う。
- 許容のチェック時だけ「点数への反映」と配点説明を表示する。フォーム内のCSSで即時切替し、チェック操作でサーバー再実行・保存しない。保存は最下部のボタンに集約する。
- 確認済み・許容した項目は入力一覧から除外し、別一覧も表示しない。保存済みの事実・本人判断は削除せず、既存の評価処理に引き続き使用する。非表示のレコードは一括保存へ送らず、他項目の保存で上書きしない。
- この画面では非表示になった項目の再編集・許容取消は提供しない。その他のカードの色・形と評価の配点は変更しない。


## 2026-09-13 応募判断の保存完了表示

As-Is：保存後に全画面を再実行し、一時的なトーストで完了を通知していたため、通知を見逃すと保存済みか判断しづらかった。
To-Be：応募判断フォームを独立したfragmentにし、保存後の全画面再実行を除去。保存成功後に現在の応募判断を更新し、ボタン直下に「応募判断〇〇を保存しました。次のアクション・期限・メモも保存済みです。」を継続表示する。入力エラー時は成功を表示しない。カードと入力欄のデザインは維持する。


## 2026-09-13：入力処理・評価整合性の更新

全ボタン・全実行への待機案内を廃止し、実際のナビゲーション操作だけに表示。検索・集計・運営者選択は部分更新。

As-Is / To-Be・対象一覧・検証範囲は [入力処理の監査記録](input_update_audit.md) を参照。


## 2026-09-13：今回の性能改善の範囲

今回採用したのは取得範囲・通信回数の削減と保存時連携。ルート、フォーム、fragment、スクロール制御、カード等の描画方法は変更しない。モーダル初回は一覧の情報を共用し、以降は最新情報を取得する。Streamlitの再実行を全面廃止する変更ではない。
