# 電車移動時間の確認（2026-09-13）

## As-Is

Google Places APIは基本情報の駅候補検索で使用。求人詳細はGoogleマップの経路リンクを開き、利用者が電車移動時間を入力していた。求人の最寄駅が空の場合は途中で表示を終了し、住所が分かっていても経路リンク・時間入力を利用できなかった。

## To-Be / 実装

- 最寄駅がある場合は既存の駅間経路を維持する。
- 最寄駅がない場合、利用者が実際の勤務地の住所を入力し、Googleマップの公共交通経路を開く。原文の会社所在地を勤務地と自動判定しない。
- 電車での片道移動時間を本人が確認・入力する。住所までの徒歩やバスを含む合計時間は入力しない。Googleからの時間の自動取得や新規Routes API連携は実装しない。
- 保存した時間は求人評価と求人比較の通勤判定に使用する。同じ時間・同じ確認先の再保存ではAI評価を更新しない。変更時は保存済みAI意味判定と数値ルールを再合成する。初回のAI評価がない場合のみバックグラウンド評価を開始する。
- 未確認の場合は従来どおり減点しない。

## 保存・互換性

既存の user_job_commute_checks を使用し、利用者・求人所有者の検証を維持する。destination_station_name は互換性のため名称を維持し、駅または本人が入力した勤務地住所を保存する。新規保存の source_type は manual:v1: に勤務地都道府県・市区町村・最寄駅・求人原文のSHA256を付加する。求人情報変更後は確認済み時間を再利用しない。従来の manual レコードは出発駅ID・到着駅の一致で引き続き利用する。DBスキーマ変更・既存データの一括更新はない。

## 検証

サービスの保存・復元、出発駅／勤務地情報変更時の無効化、旧データ互換、AppTestで住所入力→時間保存・案内表示→同値再保存時のAI再実行抑制を確認。公開環境の実データ保存・Google経路内容の正確性は自動テストの対象外。


## 2026-09-13 追補

住所はフォーム内で入力し「この住所で経路を確認する」で経路へ反映する。時間保存後は通勤欄・スコア・評価一覧を部分更新する。[監査・数値判定の設計](input_update_audit.md)参照。
