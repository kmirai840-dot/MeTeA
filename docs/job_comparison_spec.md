# MeTeA 求人関連画面構成 仕様

## 1. 基本方針

求人関連画面では、
利用者が迷いすぎないこと、
求人を探す画面と1件の求人を深く確認する画面の役割を明確に分けることを重視する。

AIは求人を大量に提示するのではなく、
求人一覧の中から「AIおすすめ求人 TOP3」を提示する。

AIおすすめ求人を別画面ですべて一覧表示する機能は作らない。

理由：
おすすめ求人が多くなるほど、
利用者にとって「結局どれを見ればよいのか」が分かりにくくなり、
意思決定の負荷が高くなるため。

AIおすすめはTOP3までに限定し、
その他の求人については、
求人一覧をAIおすすめ順に並び替えることで確認できるようにする。


# 2. 求人関連画面の全体構成

① 求人一覧（管理画面）
│
├─ AIおすすめ求人 TOP3
│
├─ 求人一覧
│    ├─ 検索・絞り込み
│    ├─ AIおすすめ順、応募判断未対応などで並び替え
│    ├─ 比較対象に選択
│    │      ↓
│    │   比較する
│    │      ↓
│    │   比較結果
│    │
│    └─ 企業名／求人名をクリック
│           ↓
│
② 求人確認画面
     │
     ├─ AIマッチング結果
     │
     ├─ マッチング詳細
     │    （希望条件との一致状況）
     │    ※初期状態では折りたたみ
     │
     ├─ 求人詳細
     │    ※「詳細を見る」で展開
     │
     └─ 応募判断
          ※画面最下部


# 3. 求人一覧（管理画面）

## 3-1. 画面の役割

登録済み求人を確認・管理し、
次に確認したい求人を選ぶための起点画面とする。

この画面内で、

- AIおすすめ求人の確認
- 求人検索
- 絞り込み
- 並び替え
- 比較対象の選択
- 個別求人への遷移

を行う。


## 3-2. AIおすすめ求人 TOP3

求人一覧上部に、
AIがおすすめする求人を最大3件表示する。

表示対象：

- おすすめ順位
- 会社名
- 募集ポジション
- AI総合マッチ度
- 希望条件との一致度
- 価値観との一致度
- 職務経歴・スキルとの一致度

など。

AIおすすめ求人はTOP3までとする。

## 3-3. 応募判断未対応求人の管理通知

求人一覧画面の目立つ位置に、
応募判断が未対応の求人件数を表示する。

表示例：

「応募判断未対応の求人が○件あります。
リストから確認をお願いします。」

この表示は、
利用者に未対応求人の存在を気づかせ、
対応漏れを防ぐための管理通知として扱う。

未対応求人を別画面で一覧表示するボタンは設けない。

求人の確認は、
同一画面内の求人一覧リストから行う。

この通知は、
求人一覧画面における管理支援のための情報であり、
AIおすすめ求人とは役割を分ける。


## 3-3. 「すべてのおすすめを見る」は設けない

おすすめ求人専用の一覧画面は作らない。

AIおすすめ求人が増えすぎると、
利用者の比較対象が増え、
判断負荷が高まるため。

TOP3以外の求人を確認したい場合は、
通常の求人一覧を

「AIおすすめ順」

で並び替えて確認できるようにする。


## 3-4. 求人一覧の並び替え

求人一覧では、
並び順を変更できるようにする。

少なくとも、

- AIおすすめ順
- 応募判断未対応×登録日が古い順への絞り込み
- 登録日順
- 更新日順
- 年収順
- 必須条件充足率順

などを追加できる構成とする。


## 3-5. 求人一覧から個別求人への遷移

求人一覧から個別求人の「求人確認画面」へ遷移する導線は、
会社名に設定したリンクへ統一する。

求人一覧内で、
募集ポジションや「詳細」ボタンなど、
複数箇所に同一の遷移導線を設けない。

利用者が求人確認画面へ進む操作を迷わないよう、
個別求人への主導線は会社名リンクに一本化する。

会社名をクリックすると、
対象求人の「求人確認画面」へ遷移する。

求人確認画面では、
AIマッチング結果、
マッチング詳細、
求人詳細、
応募判断をそれぞれ別画面として分断せず、
1求人について必要な情報を1つの画面内で確認できる構成とする。


# 4. 求人確認画面

## 4-1. 画面の役割

1つの求人について、

- 自分との相性
- 相性の根拠
- 求人そのものの情報
- 最終的な応募判断

を上から順に確認する画面とする。

利用者が、

「この求人は自分に合っているのか」
↓
「なぜそう判定されているのか」
↓
「求人条件は実際どうなっているのか」
↓
「応募するのか」

という順番で自然に判断できる構成とする。


# 5. 求人確認画面の表示順

求人確認画面は、
以下の順番で表示する。


① AIマッチング結果
↓
② マッチング詳細
   （希望条件との一致状況）
↓
③ 求人詳細
↓
④ 応募判断


# 6. AIマッチング結果

## 6-1. 初期表示位置

求人確認画面の最上部に表示する。

利用者が求人を開いた際、
最初に「自分との相性」を確認できるようにする。


## 6-2. 主な表示内容

- AI総合マッチ度
- 希望条件との一致度
- 価値観との一致度
- 職務経歴・スキルとの一致度
- 必須条件の状況
- AIからのコメント

AIからのコメントは、

- 合っている点
- 懸念点
- 次に確認すること

などに整理する。


# 7. マッチング詳細

## 7-1. 役割

AIマッチング結果の根拠を確認する。

特に、
利用者の希望条件と求人内容の一致状況を、
項目ごとに確認できるようにする。


## 7-2. 初期表示

初期状態では折りたたむ。

AIマッチング結果だけで十分な利用者に、
最初から大量の情報を見せないため。


## 7-3. 展開操作

「マッチング詳細を見る」
等のボタンを押した場合に展開する。


## 7-4. 表示内容

例：

- 項目
- 利用者の希望
- 求人内容
- 判定
- 理由・根拠

判定：

- 一致
- 一部一致
- 要確認
- 不一致

求人情報が不足している場合は、
不一致ではなく「要確認」とする。


# 8. 求人詳細

## 8-1. 役割

登録された求人情報そのものを確認する。

AIによる評価とは役割を分ける。


## 8-2. 初期表示

求人詳細の全情報を最初から表示しない。

「詳細を見る」
等の操作によって、
必要な場合のみ詳細情報を展開する。


## 8-3. 主な内容

- 基本情報
- 仕事内容
- 応募資格
- 勤務条件
- 給与・待遇
- 福利厚生
- 選考情報
- 紹介経路
- 掲載元
- メモ

など。


# 9. 応募判断

## 9-1. 配置

求人確認画面の最下部に配置する。

AIマッチング結果、
マッチング詳細、
求人詳細を確認した後に、
応募判断を行う流れとする。


## 9-2. 基本方針

AIは応募可否を最終決定しない。

AIは、

- おすすめ度
- マッチ度
- 合っている点
- 懸念点
- 確認すべき事項

を提示する。

最終的な応募判断は利用者自身が行う。


## 9-3. 応募判断

利用者が選択する応募判断として、
以下を扱う。

- 応募する
- 条件を確認して応募
- 保留
- 応募しない
- 他経路から応募する


## 9-4. その他の管理情報

必要に応じて、

- 次のアクション
- 期限
- メモ

等を入力できるようにする。


## 9-5. 他求人との比較

応募判断を行う際に、
他の求人と比較したい場合は、

「他求人と比較する」

操作を提供する。

導線：

求人確認画面
↓
応募判断
↓
他求人と比較する
↓
比較結果


# 10. 求人比較

## 10-1. 比較対象

求人一覧で、
利用者が比較したい求人を複数選択する。

「比較対象に選択」
チェックボックスを使用する。


## 10-2. 比較開始

比較対象を選択した場合、

「比較対象 ○件選択中」

を表示する。

「比較する」
ボタンから比較結果へ遷移する。


## 10-3. 比較結果

比較結果では、
選択した複数求人を横並びで比較する。

比較対象例：

- 年収
- 勤務地
- 仕事内容
- 働き方
- 福利厚生
- 希望条件との一致状況
- AIマッチ度

比較結果は、
複数求人の違いを確認することに特化する。


# 11. 画面を統合する理由

AIマッチング結果、
マッチング詳細、
求人詳細、
応募判断を別々の画面に分けすぎると、

利用者が何度も画面を行き来する必要が生じる。

求人1件について判断する際は、

AI評価
↓
根拠
↓
求人原情報
↓
応募判断

を連続して確認できる方が自然である。

そのため、
これらは「求人確認画面」という1画面の中に統合する。


# 12. 情報量の制御

求人確認画面は1画面に統合するが、
すべての情報を最初から展開しない。

初期表示：

- AIマッチング結果

必要に応じて展開：

- マッチング詳細
- 求人詳細

最後：

- 応募判断

とする。

この構成により、
情報量を確保しながら、
画面が過度に長く・複雑に見えることを防ぐ。


# 13. 最終的な画面構成

① 求人一覧（管理画面）
│
├─ AIおすすめ求人 TOP3
│
├─ 求人一覧
│    ├─ 検索・絞り込み
│    ├─ AIおすすめ順に並び替え
│    ├─ 比較対象に選択
│    │      ↓
│    │   比較する
│    │      ↓
│    │   比較結果
│    │
│    └─ 企業名／求人名をクリック
│           ↓
│
② 求人確認画面
     │
     ├─ AIマッチング結果
     │
     ├─ マッチング詳細
     │    （初期状態：折りたたみ）
     │
     ├─ 求人詳細
     │    （「詳細を見る」で表示）
     │
     └─ 応募判断
          （画面最下部）
          │
          └─ 他求人と比較する
                 ↓
              比較結果


# 14. 画面数

求人関連の主要画面は、
以下を基本とする。

1. 求人一覧（管理画面）
2. 求人確認画面
3. 比較結果

求人確認画面の内部に、

- AIマッチング結果
- マッチング詳細
- 求人詳細
- 応募判断

を配置する。

AIおすすめ求人専用の一覧画面は設けない。


# 15. 設計原則

1. AIおすすめ求人はTOP3に限定する。
2. おすすめ求人を大量提示しない。
3. TOP3以外は求人一覧の並び替えで確認する。
4. AIは応募判断を代替しない。
5. 最終的な応募判断は利用者が行う。
6. 1求人について必要な情報は1画面で確認できるようにする。
7. 詳細情報は折りたたみ・展開を利用し、情報量を制御する。
8. AI評価と求人原情報を区別する。
9. 求人比較は複数求人の違いを確認することに特化する。
10. 利用者が迷わず次の行動に進める画面構成を優先する。
