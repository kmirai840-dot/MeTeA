# 初回招待コードによる利用者登録

## As-Is / To-Be

変更前はGoogleとMeTeA双方にメールの事前登録が必要だった。変更後はGoogleログインの後に初回だけ招待コードを入力し、内部user_idを新規発行する。同じGoogle subjectで次回以降コードなしで継続する。既存Google利用者もIDを保持する。旧メール許可方式は設定で選択可能。

## 設定と認可

Secretsのaccess.registration_modeをinvite_codeにし、access.invite_codeに16文字以上のランダムコードを設定。コードの値はGit・ログ・URLに含めない。比較には定数時間比較を使用し、誤ったコードではusersに行を作らない。発行コードは24文字のランダム値。DB列追加は行わず、有効なGoogleのusers行を登録済みの根拠にする。

コード確認前もGoogle issuer、subject、確認済みメールを検査する。登録は既存のトランザクションロックで直列化する。他アカウントとのメール衝突は拒否し、ID 1の既存データへ自動紐付けしない。通常Repositoryは本人IDと有効アカウントを検査し続ける。運営者権限は別のadmin_emailsで判定し、コードで登録しても運営者にはならない。

登録済み利用者はコード変更後も使える。利用停止はusers.is_activeで行う。invite_code方式ではallowed_emailsから削除しても利用停止にならない。コードは利用回数制限付きではなく、共有された相手が新規登録できる。1人限定・使用期限・失敗回数制限は未実装。必要なら新規招待後にコードを変更する。

Google側はテストユーザー制限を外すため公開設定が必要。アプリ自体の初回招待チェックは維持する。ログイン前にもpage=privacyで保存情報・利用目的を参照できる。

## 検証

SQLiteと実Neonの専用一時スキーマで、誤ったコードの拒否、正しいコードによる登録、同一IDでの復帰、保存内容復元、2人の分離、コード変更、利用停止、偽の認証情報とメール衝突の拒否を検証する。Streamlit AppTestでフォーム送信による登録を検証する。実際の別Googleアカウントによる初回利用は、共有相手との確認が必要。
