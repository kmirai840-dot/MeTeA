## 操作

設定 →「運営者：利用者データ」→ 利用者を選択 → 保存内容を選択して確認、またはZIPをダウンロード。
ID 1などメール未連携のデータは「未連携の既存データ」と表示し、Google利用者に移管しない。
この画面からのデータ変更・削除は実装しない。論理削除済みの保存内容も含める。

## 認可・データ経路

`services/operator_service.py`で、一覧・個別取得・出力のたびに認可する。Googleモード、有効なGoogleログイン、招待リスト、DBアカウントの有効性、`access.admin_emails`を確認し、現在の内部IDと認証済みGoogleのsubject・確認済みメールが一致することを検査する。権限がない場合はURLを直接指定しても拒否する。

`admin_emails`はSecretsのみで設定する。空・未設定は全員拒否する。通常利用者には管理設定の編集機能を提供しない。運営者も`allowed_emails`への登録が必要。ローカルでは本人の許可済みGoogleメールを運営者として設定済み。公開環境のSecretsは未変更。

本人用Repositoryの制約を緩めず、別の読取専用サービスで取得する。17テーブルはuser_id、7子テーブルは所有者を持つ親へのJOINで対象を絞る。usersを含め計25テーブル。表名はコード内の固定リストで、利用者IDはSQLパラメータにする。PostgreSQLはREPEATABLE READ READ ONLY、SQLiteは読取トランザクションで一貫した内容を取得する。

## 出力

ZIPには`data.json`、データがある表のUTF-8 BOM付きCSV、説明文を格納する。JSONは空の表も含む。認証subject・画像URL・メール確認フラグや接続秘密情報は出力しない。CSVの数式開始文字はアポストロフィを付けて無害化し、JSONには原文を保持する。DB中で可逆符号化している原文もアダプタが復号して返す。

出力はメモリ上で生成し、共有キャッシュやサーバー上の出力ファイルには保存しない。ダウンロード済みファイルは運営者が保管する。権限解除で取得済みファイルを回収することはできない。小規模テスト向けに一人分を全件取得する方式で、大量データのページング・監査ログ・定期削除は未実装。

## 利用者への説明

`ui/data_notice.py`を共通表示元とし、Googleログインボタンの前と設定画面に表示する。保存項目、継続利用・支援・不具合調査・改善という利用目的、運営者の閲覧と出力、Neonとバックアップ、保存操作のタイミングを説明する。
AI処理ではOpenAIに必要な入力・文書内容が送られ、自動分析もあること、駅検索ではGoogleに検索語が送られることを説明する。外部サービスの学習利用・保持期間について、確認していない保証は記載しない。
自動削除期限は未設定である旨と、招待時の連絡手段で削除・訂正を依頼する方法を明記する。これは説明表示であり、同意履歴をDBに記録する機能や自動消去の実装ではない。

## 検証

`tests/test_operator.py`は既存の2利用者・25テーブルのテスト用データを利用する。未ログイン、一般利用者、許可解除、無効アカウント、subjectの不一致、未確認メール、legacyモードを拒否すること、子テーブルを含めた分離、ZIP内容、CSV数式対策を検査する。
