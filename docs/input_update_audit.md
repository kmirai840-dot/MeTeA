# 入力時の再読み込み・数値評価の整合性（2026-09-13）

## As-Is（今回確認した問題）

- 求人登録、希望条件、価値観、就活の軸の編集、職務経歴、選考結果・予定・準備メモの一部で、入力変更ごとにサーバー処理が動いていた。
- ナビゲーションの共通処理が、画面遷移を伴わない処理にも「画面が切り替わるまで」の案内を表示していた。
- 通勤時間の変更がAI再評価の成功に依存し、AIが失敗すると確認済み時間と以前の「未確認」の評価が併存した。
- 年収は下限を優先して不一致判定。構造化された年収欄が空だと、原文に想定年収があっても月給×12を使っていた。

## To-Be（実装）

| 対象 | 入力中 | 明示操作時 |
| --- | --- | --- |
| 基本情報・スキル | 既存フォームを維持 | 保存・駅検索で送信 |
| 希望条件・価値観・就活の軸編集・職務経歴 | フォーム内に保持 | 一時保存・保存・追加・並べ替え等の操作で送信 |
| 求人登録（本文・URL・整理後の求人情報） | フォーム内に保持 | 読み取り・確認へ進むボタンで送信 |
| 応募判断・確認結果 | 既存の一括送信を維持 | 保存で部分更新 |
| 選考結果・次の予定・延期・準備メモ・AI文章編集 | フォーム内に保持 | 登録・保存・生成等の操作で送信 |
| 一覧検索・比較対象・集計期間・運営者の対象選択 | 操作結果を表示する部分更新 | 入力保存とは区別し、アプリ全体は再実行しない |
| ファイルアップロード・削除確認 | 明示的な操作として扱う | 既存の確認・実行操作を維持 |

条件付き欄はブラウザ内で開閉する。従業員数、試用期間、勤務地の優先度、在職中、次回選考日などの選択変更ではサーバーへ送信しない。非表示の値を採用するかは保存時にサーバーで再判定する。希望条件の旧下書きキーは読み替え、入力済み内容を維持する。

カードの配色・配置を維持。Streamlitの選択色を共通トークン `#146cff` に統一。ローカル検証サーバーもリポジトリの設定を読み込む。

## 数値評価

- 原文に明記された想定年収範囲を、年収欄が未設定の場合に利用する。月給×12へのフォールバックより優先する。年収例は範囲として採用しない。
- 求人上限も最低許容年収未満なら不一致。下限が未満でも範囲が最低許容額を含む場合は一部一致とし、提示額の確認を案内する。上限不明時は要確認。
- 下限が最低許容額以上、希望年収未満で、上限が希望年収以上なら、その両方を説明する。上限の金額が必ず提示されるとは扱わない。
- 確認済み通勤時間は出発駅・求人の勤務地情報との整合性を検証して利用する。
- 保存済みAI意味判定を再利用してルール判定と点数・説明を再合成する。数値変更のためにAIを再実行しない。AI評価がない求人は通常の初回評価を行う。
- 本人の所有する求人・確認記録だけを取得。入力値は変更せず派生した評価を更新し、署名一致なら再保存しない。処理中のAI評価への書き戻しは行わない。既存の失敗・更新待ち状態は維持する。

## 検証と範囲

- AppTestで求人の条件付き入力の送信、バリデーション時の入力維持、希望条件の旧下書き復元、各編集フォーム、選考結果・予定の一回送信、保存して次への遷移を検証。
- 数値テストで年収の境界・範囲・原文優先・年収例除外、通勤の保存値反映・勤務地不一致・同一入力の再処理抑制・AI失敗状態維持を検証。
- ブラウザのローカル検証で、勤務地選択→市区町村入力後も実行回数1、求人のチェック・試用期間変更でも実行回数1を確認。選択色は rgb(20,108,255)。
- 全画面の入力呼び出しを静的確認。全実データ操作を本番で網羅したという意味ではない。公開環境でテスト用入力の新規保存は行わない。
- 通信・DB・AIに時間がかかる保存処理自体をゼロにはしない。入力変更と明示的な処理実行を分離する。
